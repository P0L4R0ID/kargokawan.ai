# Render deployment for EasyParcel OAuth readiness

For the current optional OIDC-verified pilot draft API, see [pilot_auth_integration.md](pilot_auth_integration.md). This document describes the separate EasyParcel OAuth callback, which remains disabled.

**Current state:** KargoKawan's public frontend origin is **https://kargokawan.streamlit.app**. A health-only OAuth backend is reported at **https://kargokawan-oauth.onrender.com** and the EasyParcel Developer Hub app settings are reported saved. No live OAuth authentication has succeeded; Codex could not reach the Render host from this environment to verify its current deployment. The code for the production backend deliberately returns **403** for `/oauth/easyparcel/start` and `/oauth/easyparcel/callback`, even if credentials are configured. Its `/health` route works without secrets. There is no Connect EasyParcel action in Streamlit.

## Why account linking is disabled

The current public Streamlit app has no verified login. Its delivery jobs live in a local SQLite file (`.data/delivery_jobs.sqlite`) without owner IDs or per-user access checks. A Streamlit session, browser cookie, or supplied job ID cannot prove who owns an order. Giving this frontend OAuth tokens would risk cross-user access to accounts and jobs. The backend's one-time state, Secure/HttpOnly/SameSite=Lax cookie, HTTPS redirect validation, Basic-auth token exchange and encrypted SQLite storage have mock tests, but they do **not** solve user identity. Production routes stay closed until authenticated users, owner-scoped job storage, a secure frontend-to-backend session bridge, and authorised account-link permissions are implemented and reviewed. The backend does not book, pay, cancel, or create shipments. The existing **Individual API key** quote adapter and manual entry are separate from this Open API OAuth service.

## What Codex prepared

- `Dockerfile.oauth` builds a one-worker Gunicorn WSGI web service. It listens on `0.0.0.0:${PORT}` (default 8080), sets a restrictive file-creation mask, and does not write access logs containing callback codes.
- `/health` returns 200. OAuth routes return 403 in the production entrypoint.
- The test-only flow uses cryptographic state, a short-lived server-side state record, exact callback host validation, single-use code exchange and encrypted token storage. Tests inject a fake provider transport; the production entrypoint cannot turn on this flow with an environment variable.
- A separate `EasyParcelOpenApiAdapter` returns `NOT_CONNECTED` and makes no API calls.

The callback path is exactly `/oauth/easyparcel/callback`. Render terminates public HTTPS before forwarding to the container; the backend validates the configured public HTTPS redirect and issues `Secure` cookies. Do not infer a public HTTPS origin from internal `wsgi.url_scheme`. The service intentionally does not trust user-supplied forwarded headers to choose its callback URL.

## Render setup, when you are ready to deploy the disabled backend

1. Create a [Render account](https://dashboard.render.com/) and connect GitHub in Render. Grant access to `P0L4R0ID/kargokawan.ai`.
2. Choose **New → Web Service**, select the repository, and select branch `feature/secure-oauth-deployment` (or a reviewed deployment branch containing it). Select **Docker** as the runtime, set **Dockerfile Path** to `Dockerfile.oauth`, and leave Docker Command blank so its `CMD` is used. Select a region appropriate for your account and users.
3. Choose a **paid web-service plan with a persistent disk** before any future token storage is enabled. Render's free web-service filesystem is ephemeral and does not support a disk. In **Advanced → Disk**, mount a disk at `/var/data`; only that path persists. Use one instance. A managed Render Postgres database is an alternative, but this repository does not yet contain a Postgres token-store implementation.
4. In **Advanced**, set **Health Check Path** to `/health`. The service listens on Render's `PORT` environment value. Do not override the Docker start command. Render provides the public HTTPS `onrender.com` URL after service creation; verify it in the dashboard. **The reported backend hostname is `kargokawan-oauth.onrender.com`; verify it in your Render dashboard before changing settings.**
5. For the disabled health-only deployment, do not add OAuth secrets. The backend does not need them to answer `/health`. Verify `https://YOUR-ACTUAL-RENDER-HOST/health` returns `ok`, and `/oauth/easyparcel/start` returns 403. Do not use the placeholder as an actual URL.
6. Once user authentication and owner-scoped jobs are implemented, register the app in [EasyParcel Developer Hub](https://api.easyparcel.com/). Set **Platform URL** to `https://kargokawan.streamlit.app`. Copy your **actual** Render HTTPS origin and append `/oauth/easyparcel/callback` for **Allowed Redirect URI**. Enter that exact value in EasyParcel and in `EASYPARCEL_OAUTH_REDIRECT_URI`. Do not register a placeholder or the Streamlit URL as the callback.
7. Store these as Render **secret environment variables**, never in Git or a Streamlit widget: `EASYPARCEL_OAUTH_PLATFORM_URL=https://kargokawan.streamlit.app`, `EASYPARCEL_OAUTH_CLIENT_ID`, `EASYPARCEL_OAUTH_CLIENT_SECRET`, `EASYPARCEL_OAUTH_REDIRECT_URI`, `EASYPARCEL_OAUTH_FERNET_KEY`, and `EASYPARCEL_OAUTH_DB=/var/data/oauth.sqlite`. Generate and preserve a stable Fernet key with `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` on a trusted machine; do not paste the result into chat or logs. Restrict disk access and backups. Rotation requires migrating existing ciphertext.
8. **Do not attempt a real OAuth handshake yet.** The start/callback routes remain closed by design. After identity, ownership checks, safe account linking, and a security review are complete, enable the flow in a separately reviewed change. Then conduct an authorised EasyParcel sandbox handshake, confirm state and account identity, exercise token refresh and revocation if supported, and show CONNECTED only after the backend verifies success.

If access must be disabled urgently, remove or revoke the Developer Hub app credentials and connected account authorization in EasyParcel, remove credentials from Render, stop the service, and revoke/rotate the Fernet key only after preserving any data needed for incident review. No OAuth credential is presently connected.

## Persistent storage and plan limitations

[Render's disk documentation](https://render.com/docs/disks) says filesystem writes are ephemeral by default, and persistent disks attach to **paid** web services. A disk is available to one service instance and prevents zero-downtime deploys. `EASYPARCEL_OAUTH_DB` must point under the disk mount before any real token may be stored. The existing Streamlit Community Cloud delivery-job SQLite file is also local and has no shared persistent, user-isolated storage; do not use it for real multi-user customer operations. Before real account linking, move job ownership to an authenticated persistent datastore and enforce owner checks on every read and mutation.

Render's [Docker guide](https://render.com/docs/docker) documents selecting a custom Dockerfile, its [web-service guide](https://render.com/docs/web-services) documents branch, plan, env and disk settings, and its [health-check guide](https://render.com/docs/health-checks) documents an HTTP health path. We intentionally did **not** create `render.yaml`: the paid plan, disk and final hostname require an account-specific choice, and a template could be mistaken for an active secure deployment.

EasyParcel's [official Open API authentication source](https://github.com/easyparcel/OpenAPI/blob/main/source/includes/2026-09/_authentication.md) documents the authorization-code and refresh-token request fields. The [Developer Hub source](https://github.com/easyparcel/OpenAPI/blob/main/source/includes/2026-09/_developerhub.md) describes app registration and redirect URI. The documentation does not establish a narrow scope name for this use case; no optional scope is requested. The callback contract is mocked in tests only. No provider tokens, authenticated quotations, or deployment have been verified.
