# Provider quotation setup

EasyParcel Malaysia's [Individual API documentation](https://developers.easyparcel.com/?c=Malaysia&pg=DocAPI&type=Individual) documents `EPRateCheckingBulk`, an account API key, Malaysian sender/receiver postcodes and states, parcel weight and optional dimensions. This implementation sends one parcel rate check to `https://connect.easyparcel.my/?ac=EPRateCheckingBulk` only after a user clicks **Fetch available quotations**. Use an authorised EasyParcel account and place `EASYPARCEL_API_KEY` in the server environment or Streamlit secrets. The key is never shown or saved in delivery jobs. The [official demo page](https://developers.easyparcel.com/?c=Malaysia&pg=Demo) lists a demo rate endpoint; the app does not use its HTTP demo endpoint because live connections require HTTPS. Confirm account permission and any provider rate limits with EasyParcel before production use.

Select a delivery job and one order, enter the origin and destination Malaysian states exactly as the provider expects, then click **Fetch available quotations**. Order postcodes, weight, and dimensions come from the job. If credentials are absent, the status is **NOT_CONNECTED** and the existing manual quote form remains usable. A successful HTTP response alone is insufficient: the adapter checks the provider's success fields and rate structure. Authentication failures, timeouts, and rate limits show sanitized **ERROR** results.

Returned EasyParcel rates preserve courier/service, account tier (member or non-member), displayed MYR amount, optional shipping/add-on amounts, delivery text, rate ID and collection time. They are **INCOMPLETE observations**, excluded from the optimiser. The current response fields do not establish an all-in payable total, tax/surcharge treatment, or quote expiry for a specific job. Unknown fields stay unknown. The manual evidence workflow is still required to obtain and review a complete payable quotation. The app does not promote an observed rate to an approved shipping plan automatically.

[Lalamove v3 documentation](https://developers.lalamove.com/) confirms `POST /v3/quotations`, HMAC-SHA256 request signing with a partner API key and secret, a Malaysia market, coordinate-based ordered stops, a quotation ID, expiry and price breakdown in successful responses. Obtain sandbox credentials in the Lalamove Partner Portal (`LALAMOVE_API_KEY`, `LALAMOVE_API_SECRET`). The app currently checks credential presence only; it **does not send sandbox or production Lalamove requests**. Exact coordinates, supported city/service type, capacity, and account permissions still need to be established from provider evidence. Postcodes alone are never converted into coordinates. The manual Lalamove evidence form remains available.

The read-only `ProviderQuoteTools` boundary can report missing facts and connection state or request EasyParcel rates with a six-call limit. It does not create, modify, book or pay for shipments. The existing simulated assistant remains isolated from real job data. Automated provider tests use synthetic mock responses, not real credentials or live API calls. No live authentication succeeded during development.
