# Authenticated pilot planning, review and approval

This branch connects private pilot **draft** jobs and manually recorded quotation evidence to KargoKawan's existing deterministic mixed-method optimiser. It is not deployed by this branch. The public fictional demo and its local operations workflow are separate. EasyParcel OAuth remains disabled (HTTP 403); no live provider quote, booking, payment, shipment creation or tracking action occurs.

## What the operator can do

1. Sign in on the reported pilot frontend, `https://kargokawanai-pilot.streamlit.app`, using the configured Google OIDC operator account. Render independently checks the signed ID token's issuer, audience, expiry and exact allowlisted subject on every private API request.
2. Upload a fictional order CSV, create a **private pilot job**, and select it. Orders retain five-digit postcodes and delivery deadlines.
3. Upload one reviewed quotation row at a time through the existing 24-field research quote CSV route, or correct a saved quote draft. Manual records remain `USER_IMPORTED_UNVERIFIED`; public starting prices stay `PUBLIC_REFERENCE` and cannot be selected. The importer does not authenticate a provider.
4. Under **Private quote-backed planning**, mark any quoted provider known to be unavailable, then select **Request private plan**. The backend loads only that job's orders, quote drafts and availability. It normalizes the stored CSV evidence, reuses `hybrid_quotes.review` and `mixed_method.optimize`, and returns **NOT READY** with per-order quotation tasks if no complete exact cover exists. Expired, partial, incompatible, synthetic and public-reference records are excluded. A missing all-courier baseline is shown as unavailable, never estimated.
5. Select a proposal and review its quote IDs, providers, order coverage, MYR totals, deadlines, validity, source references and quote exclusions. `READY` means the solver proved the minimum-cost exact cover; `SOLVER LIMITED` identifies a feasible result without an optimality claim. A proposal remains **NOT A BOOKING**.
6. Select **Approve this private plan** to approve explicitly. The backend locks the job, checks the proposal version and a fingerprint of orders, quote content and versions, availability and job version, then re-evaluates quote eligibility. Order edits, quote edits, provider changes and quote expiry reject stale approval. Approval records an append-only audit event; it does not communicate with carriers.
7. Reload and select **Download approved manifest — NOT A BOOKING**. The CSV lists order IDs, postcodes, deadlines, selected providers, quote references and quoted **group** totals. It excludes recipients and all identity/database tokens. If inputs or eligibility change after approval, the old manifest is blocked as outdated. Use a fresh proposal and approval.

The private API adds `/pilot/jobs/{id}/availability`, `/proposals`, `/proposals/{proposal_id}`, `/proposals/{proposal_id}/approval`, `/proposals/{proposal_id}/manifest`, and `/audit`. Only the PostgreSQL-backed pilot store serves these routes. The backend requires a verified operator ID token before all reads and writes. Proposal creation and approval append audit events in the private `kargokawan_pilot` schema; a database trigger rejects audit updates and deletes. No client-supplied plan price, order list or provider authentication claim is accepted by the plan route.

## Deployment and limits

The backend Docker image now includes NumPy, SciPy and the existing quote normalizer/optimiser modules. This increases image size and may affect cold-start memory on Render Free; measure it on the actual service before enabling the new branch. The existing Render-only PostgreSQL and OIDC settings in [supabase_pilot_setup.md](supabase_pilot_setup.md) remain required. Do not put database credentials or ID tokens in Streamlit widgets, logs or manifests. No new EasyParcel credentials are required.

The single-operator Supabase schema migration advances `pilot_schema_versions` from 1 to 2, adding provider availability, proposals and append-only audit records. It preserves existing private draft jobs and quotes. Make a tested off-site backup before any manual deployment. The code does not migrate the public fictional demo or local SQLite jobs. Private planning is a separate draft-and-approval workflow; it does not turn an approved plan into a carrier booking or into the older local `JobStore` lifecycle. Future real-customer use still needs a live security review, tested Render/Supabase connectivity, backup/restore procedures, provider evidence verification, and explicit operational handling after approval.

Tests use a disposable local PostgreSQL instance with **synthetic** quotation fixtures. They do not prove a real provider quote, Google sign-in or live Render deployment.
