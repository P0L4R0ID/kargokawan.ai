# Integrated KargoKawan demo (2–3 minutes)

1. Open Streamlit and select **Load Demo Scenario**. The permanent **SIMULATED DEMO — NOT REAL CARRIER PRICES** banner identifies four fictional postcode-specific orders. Show the RM80 standalone courier baseline against the RM55 mixed-method proposal. The selected three-stop vehicle quote covers three explicit stops; a parcel quote covers the fourth. Quote IDs and solver status are visible.
2. Select **Preview demo plan**, then **Approve demo proposal**. Explain that approval records a local proposal, never a carrier booking. Check **Simulate disruption: vehicle provider unavailable**. The approval clears and the plan changes to four fictional parcel quotes costing RM80. Preview and approve the replacement.
3. Scroll to **What do you need delivered?** and select **Load synthetic nationwide intake sample**. Show the 15-order checklist: exact postcodes and customer details must be supplied by the user, never inferred. Create a persistent job to show its ID, state and audit events.
4. Explain the real-data handoff: with complete manually imported EasyParcel and Lalamove quotes, a user can approve a mixed quote plan, then select **Create delivery job from approved quote plan** after completing recipient details. The job enters `READY_FOR_REVIEW` and requires a **separate job approval**. Its manifest lists each order's selected method and quote reference and states **NOT A BOOKING**.
5. The user prepares packages and books manually with the provider. Only an external confirmation reference, tracking ID and evidence can mark the job booked; transit and delivery also require evidence. No API calls, bookings or payments happen in the app.
