# Restricted EasyParcel pilot: security gate and hosting steps

Pilot draft jobs now have an OIDC-verified Render API behind a persistent-disk gate. See [pilot_auth_integration.md](pilot_auth_integration.md) for the current implementation and configuration. EasyParcel OAuth itself remains disabled.

## Current deployment facts

The public Streamlit frontend is `https://kargokawan.streamlit.app`. The user reports a health-only Render backend at `https://kargokawan-oauth.onrender.com`, with EasyParcel callback registered as `https://kargokawan-oauth.onrender.com/oauth/easyparcel/callback`. EasyParcel Developer Hub app settings have been saved. This development environment could not reach the Render host (network proxy returned 403), so live health and the registered app cannot be independently verified here. **No live EasyParcel account is linked.** The production OAuth start and callback routes remain hard-disabled (403), even when environment variables are set.

The [EasyParcel Open API OAuth reference](https://github.com/easyparcel/OpenAPI/blob/main/source/includes/2026-09/_authentication.md) documents authorization code, state, Basic client authentication, token exchange and refresh. This code pins the known public frontend origin and exact registered backend callback. It does not request an undocumented scope or call a booking/payment endpoint.

## Architecture and gaps

The public Streamlit app currently has no verified user login. Streamlit's [OIDC support](https://docs.streamlit.io/develop/concepts/connections/authentication) can authenticate a user in the frontend, but `st.user` claims or a Streamlit session ID are **not** a server-verified identity at Render. A secure account-link bridge would need Render to verify a signed identity assertion or manage its own authenticated session; that bridge is not implemented. Its operator subject must be allowlisted on the backend. A user-entered job ID, public browser cookie, or simple password field is insufficient.

The existing `.data/delivery_jobs.sqlite` was one shared local database. The UI now uses a random per-session local demo database instead, keeping the old sample, manual quote and competition workflows available **for fictional data only**. These databases are disposable and not suitable for real customer jobs. The legacy `JobStore` remains for local tests and offline demos; it is not the real pilot store. The new `PilotStore` is isolated from the public UI: it verifies a signed OIDC identity token on **every** job/quote read and mutation, allows only one configured operator subject, checks owner IDs in SQL, and rejects synthetic or user-claimed `LIVE_AUTHENTICATED` quote drafts. Edits to orders clear its old quotes. It requires an existing persistent storage mount. It has no HTTP route or Streamlit bridge, so no public user can access it yet.

The OAuth callback's test-only flow retains one-time state, cookie binding, exact callback host checking, server-side Basic-auth code exchange, and encrypted token storage. Production does not expose initiation, status, callback exchange, token lookup or refresh. A cookie and state alone do not identify the operator or prove which EasyParcel account granted access. The current test flow is **not** an authorised pilot connection.

## Hosting changes required before a real pilot

1. On Render, **upgrade the web service to a paid plan and attach a persistent disk** mounted at `/var/data` before storing real tokens or jobs. Set `EASYPARCEL_OAUTH_DB=/var/data/oauth.sqlite` and place a future pilot jobs database under the same mounted path. This is a cost-bearing step: [Render says Free web services have ephemeral filesystems and cannot attach disks](https://render.com/docs/free). A managed persistent database is an alternative, but this code currently supports SQLite only; Render's free Postgres is time-limited and is not a durable production replacement.
2. Obtain and configure a trusted OIDC identity provider for the single operator. Provision a stable, exact operator **subject ID** (not an email address). Configure issuer, audience, HTTPS JWKS URL and subject on the backend. `PilotStore` currently accepts these in server-side constructor arguments; deployment environment variable names and HTTP identity endpoints must be added in a reviewed integration change. The Streamlit login must be configured separately with OIDC client settings in Streamlit secrets.
3. Add a backend-authenticated session bridge from Streamlit to Render that does not expose EasyParcel tokens to browser JavaScript, widgets or query strings. The backend must independently verify each identity assertion and bind the OAuth state and provider account to the same operator. A successful provider response must be checked against the expected EasyParcel account before it can be marked CONNECTED. No such account-verification handoff exists yet.
4. Migrate real customer jobs and quote evidence to the owner-scoped persistent store, enforcing ownership on every API and every operation, and remove public access to the legacy local jobs. Add data retention, backups, key rotation and provider revocation procedures. Test this on the paid storage environment.
5. Only after the above are reviewed, enable OAuth routes and conduct an authorised sandbox handshake. Confirm token response, expiry, refresh, account identity and read-only quotation response. Full-payable amount, tax, surcharges, member conditions and validity must still pass quote review before optimisation. Human approval remains mandatory for any plan; no booking or payment is in scope.

The exact Platform URL is `https://kargokawan.streamlit.app`. The exact registered Allowed Redirect URI is `https://kargokawan-oauth.onrender.com/oauth/easyparcel/callback`. Do not substitute a Streamlit `/oauth2callback` path: that path would belong to a separate **operator OIDC login**, not EasyParcel's Render callback.

## Verification completed in this branch

Mock tests cover signed identity verification, unauthenticated and wrong-operator rejection, owner-scoped job and quote reads/mutations, test-only OAuth state/replay and encrypted token storage, and production-disabled OAuth routes.
