# Festival Idea Putrajaya · five-minute guided demo

The public journey uses **fictional orders and prices; no real bookings**. It needs no login, CSV or courier credential. Its session data never enters private PostgreSQL pilot jobs.

1. **0:00–0:40 · Start.** Open the first top-level tab, **Five-order walkthrough**, under the KargoKawan heading. Click **Try with 5 example deliveries**. The single workspace opens at step **Orders**. Five cards show destinations, postcodes, weight, dimensions and deadlines from validated order data.
2. **0:40–1:35 · Review deliveries.** Show that three destinations are in Kuala Lumpur and two are George Town and Johor Bahru. Open **Check complete order details and change a deadline** if judges want input evidence. Click **Review delivery plan**. The workflow advances to **Plan** without manual tab switching.
3. **1:35–2:25 · Understand the suggestion.** The cards show a three-stop van plus two individual courier parcels, with group costs and order coverage. The existing exact-cover optimiser calculates an assumed **RM113** total. A complete eligible all-courier comparison is **RM132**, an assumed **RM19** difference. These are fictional software-test assumptions, not genuine rates or savings. Expand **How this was calculated** for quote IDs, exclusions, source references and truthful solver status. The primary recommendation is generated from selected groups, not hard-coded prices.
4. **2:25–3:15 · Make the human decision.** Click **Review this plan**. The workspace advances to **Approve**, showing the groups and assumed total again. No manifest is available. Click **Approve this plan**. The existing fingerprint and eligibility checks run before approval, then the workspace advances to **Prepare**. **Change plan** returns without approval.
5. **3:15–4:00 · Prepare.** Download **Download fictional preparation manifest — NOT A BOOKING**. It contains five rows. Optionally click **Mark fictional packages prepared**; this is an in-session marker, not a booking or dispatch. Real-world next tasks remain guidance: verify carrier prices and addresses, pack and label parcels, and arrange real bookings outside this demo.
6. **4:00–5:00 · Show adaptation and honesty.** Open **Something changed? · Demo controls and activity** and click **Simulate van unavailable**. The approval and preparation marker clear, and the workspace returns to **Plan**. The optimiser now recommends standalone parcels for an assumed **RM132**, shows the prior **RM113**, the **RM19** increase and changed quote selections. A fresh review and approval are required. To show a blocker, return to **Orders**, change FEST004's deadline to one day, then review the plan. It identifies FEST004 as uncovered, shows no unsupported cost comparison, and offers **Review deliveries** as recovery.

**Before and after:** the previous nested Overview, Orders, Plan, Approval and Activity tabs required operators to find the next screen themselves. This version moves through one guarded workspace, with backward inspection and one main action at each stage. Recommendation cards and short route language precede optional technical evidence. The same validator, quote review, deterministic optimiser, preview, approval and manifest functions remain authoritative.

The separate top-level **Private Pilot** still requires Google OIDC and owner-scoped Render/Supabase access. **Advanced & other demos** holds previous tools. The demo makes no carrier API calls; EasyParcel OAuth remains disabled. Session history is only fictional activity and disappears with the session. A feasible solver-limited plan is never called globally optimal.
